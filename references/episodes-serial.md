# Episodes Serial — 连载分集通用工艺

用途：把一个已成立的故事组织成可持续交接、逐集验收的连载。
适用条件：作品包含两个及以上相互承接的单元；单集独立作品不适用。
与相邻文件分界：本文件管所有形式的分集；`story-short-drama.md` 只管爽剧 lane；张力门仍在 `dramatic-tension-engine.md`，此处不复制。

## 1. 适用条件与入口

- 先确认交付是连载而非单条拆段；单集作品直接走主路径。
- 形式、主题、总时长、场景与成本边界已定后，才用本文件把模型压到执行位；未定形式时仍由开放创意导演做选择。
- 入口必须有：故事原型、当前人物/关系状态、结局方向、制作限制、必须保留项、禁止事项。缺项写进 `### 默认假设` 按默认值补齐并标可改，不因缺项推迟大纲。

## 2. 分集前分析

分析先于正文，但与大纲在同一条回复内交付：
1. 写清本集核心任务、主角目标、冲突双方诉求、主要情绪、必交代信息、结果与代价、结尾卡点和下集承接。
2. 核对「核心期待能否支撑计划集数」。这是可行性诊断项；必须同时看实际分布，不能据此把它宣称为唯一门。
3. 按作者层时间顺序列全知故事原型：人物身世、动机、目的、行为，以及事件原因、过程、结局；再决定隐藏什么、何时揭露。
4. 跑逐集专项：本集是否自足，又是否推动全局；单查全稿或单查本集都不够。
5. 在文字阶段查时间顺序、行动耗时、人物位置、道具来去；关系则核对身份、亲属、感情、利益的上集末态，变化必须有铺垫。
6. 大纲有逻辑漏洞、核心期待不足或时长承载不下时，先给调整方案，随即按方案默认版写出大纲，标「可改」；禁止用对白把空缺填满。7. 单集节拍按「承接 → 建立冲突 → 升级 → 情绪兑现 → 卡点」组织，时长按核心情绪分配，不平均切段。
8. 卡点与前集查重；同一种卡点连续复用，视为疲劳风险。
9. 逐集按 △ 动作和台词估时，看事件装不装得进目标单集时长。装不下就拆集或删事件，不靠 OS、旁白把关键推理压进去。

## 3. 三层结构与交付顺序

三层依次锁定，后层不得反写前层事实：

| 层 | 必须产物 | 作用 |
|---|---|---|
| 全剧层 | 背景、人设、故事大纲、全知故事原型、大悬念 | 锁定世界事实、结局方向与根本问题 |
| 阶段层 | 覆盖集数、阶段目标、任务/阻碍、核心冲突、情绪基调、阶段兑现、下阶段入口 | 防止逐集扩写时主线漂移 |
| 单集层 | 节拍、正文、检查、双向接口 | 只执行本集已经分配的变化与欠账 |

扩写顺序固定为：背景 → 人设 → 大纲 → 节拍 → 正文 → 检查；节拍不能并进大纲。完整交付顺序是：故事诊断 → 补充设定 → 阶段结构 → **人物成长线** → 分集大纲 → **伏笔回收表** → 节奏自检。两个加粗产物不可省。

悬念只改「隐藏清单 + 揭露顺序」：大悬念给出作品层根本问题；小悬念逐集记录新提出项、已揭晓项、以及揭晓后离根本答案近了哪一步。情绪铺垫、节奏控制、信息释放是并行诊断杠杆，不是封闭分类，不能用多加反转去补另两项的空缺。

可维护一份只写结构功能、不写具体剧情的「章节形状库」，允许多个形状组合。爽剧 lane 可另参考其开场、爆发与集尾模块，但不得把该经验升成所有连载的通用结构。

## 4. 单集双向接口

输入至少包含：

- `上一集卡点`：上一集留下的同一问题及其真实末态；
- `本集任务`：当前目标、主要阻力、必须改变的变量；
- `制作约束`：场景限制、必须保留、需避免；
- `状态载体`：不可改设定、角色当前状态、已确认节点、未回收伏笔、禁止事项。

输出末尾固定三行：

```text
结果与代价：……
结尾卡点：……（必须可视化）
下一集需承接的问题：……
```

逐场继续使用「承接 / 本场目标 / 禁止事项」三槽，并在场后产出交接摘要。长上下文只压缩为下游必需事实：情节节点、确需逐字继承的人物声音、未回收伏笔、角色情感进展；不套固定压缩比例。世界/结局禁令进状态载体，知情禁令按场更新。

## 5. 场级六类变化

每场先声明发生哪一种变化。相对现有张力门，本文件只新增四类场级检查：

- 信息：谁知道了什么，因而改了判断或动作；
- 关系：权力、亲疏、信任或利益位置发生可指认改变；
- 目标：人物开始、放弃或改换了当前行动目标；
- 情绪：情绪递进或转化，并由动作、选择或关系结果证明。

「受阻」「冲突升级」直接回指 `dramatic-tension-engine.md` 的阻力/升级门，不另造判据。集级再检查至少有一项有效推进；这是一项开集合下限，不是六项配额。优先复用已锁角色与场景，但成本复用不能替代必要变化。

## 6. 集尾卡点与承接成对判定

第一关沿用张力门的五类集尾卡点：身份暴露、关系反转、危险逼近、关键选择、利益变化。可补「证据出现」，但前提是证据已被前文预示或已经在场；卡的是它被看见的时刻，不是凭空出现。

第二关另用承接清单检查：危机、反转、秘密、选择、情绪爆点中，本集留下了哪一种；下一集开头是否继续处理**同一个**问题。两套五类用途不同，不合并。

把续看点写成一句明确问题，为什么、何时、能否只是可用句型，不是穷尽格式。卡点若只有强行打断而无代价或待承接问题，两关都不通过。

付费卡点要写明为什么放在这一集。模型和各家 skill 的惯性是把首个付费卡点放在第 10 集，不能拿惯性当理由。卡点集的结尾要放全剧此刻最强的未答问题。常见的有效形态是先让主角刚赢一局，紧接着来一个更大、可见的威胁。卡点集的最后一场单独读一遍，问自己想不想付费看下一集。

当系列用同一触发器反复切换类型或世界时，每轮都要让后果更难收回，并在回到现实关系后揭示触发者；再次触发可以留作下一轮钩子，但不得只换皮而不承接前轮因果。

## 7. 伏笔台账

每条伏笔记录：稳定 ID、埋设场次、观众/人物当前所知、预定作用、最晚回收集或场、当前状态。尚未分配用途但已显著出现的物件，标为「象征意义待用」，不得默认为废笔。

改稿或压缩后做回归检查：人物逻辑是否断裂、伏笔是否被误删、情绪阶梯是否缺级。每条修复建议同时点名可能受影响的下游集与场；变更完成后重跑相关台账与承接。

## 8. 注水检测

先划边界：慢节奏、铺垫、留白本身不等于注水；判断的是信息或局面是否有增量。

按以下顺序跑逐段表：段落位置 → 剧情功能 → 信息增量 → 人物/剧情局面变化 → 风险级别（低/中/高）→ 判断理由 → 处理建议。先标功能，再查重复信息、重复情绪、冲突踏步、重复场景功能、无效对话和缺少增量；伪悬念还要问人物为何不能立刻行动、解释或出示证据。

处理建议只取五值：`保留 / 压缩 / 合并 / 删除 / 改为行动推进`。最后才跑可删除性：假设删掉该段，后续是否仍顺利成立；它是最终定级的二元判据，不是流程入口。

再跑跨段归类，把重复信息、情绪、冲突、场景功能、台词含义放在一起比较。机制复现时逐次压缩，最终可用停顿代替重演；具体压缩比例不照搬个案。任何压缩都回到伏笔台账做回归。

## 9. 集数节律参考区间

仅作可被 brief 覆盖的平台经验：前 `3 TODO_VERIFY_LIVE` 集用于建立处境、核心矛盾与追剧期待；每 `3–5 TODO_VERIFY_LIVE` 集可形成小单元；每 `8–12 TODO_VERIFY_LIVE` 集可完成阶段目标；前 `10 TODO_VERIFY_LIVE` 集内可安排首次明显兑现。它们不进任何门，实际节律由题材、单集长度、平台与 brief 决定。

## 10. 分段交付与交接

- 长连载先交阶段结构，再按当次模型上下文和单次输出上限分组；批量大小查 live schema / receipts，不写永久数字。
- 分集表同时对账角色、场景、镜头与项目需要的道具/声音资产；缺口先补资产，不靠重复抽卡碰运气。
- scene block 可按成片顺序拆文件，稳定 descriptor 与世界级 look/camera 作为版本化常量；只有长项目采用，短条目不强加工程开销。
- 写 prompt 前建立节拍/镜头时长与生成预算对账表；帧率、倍数和预算比例按当前项目测算，不照搬案例。
- 首段计入方法学费，段末把已验证规则冻结成文档；不要据单个案例主动把所有高难镜头前置。成本按运动体、接触点与抓握等连接复杂度估，不照搬案例倍数。
- 风格锚与身份锚分开维护；预设只给一致起点，不是合格成品。
- 是否省略分镜必须显式记成本：若用首批 take 兼作预演，调度问题会晚到生成阶段才暴露，不能把它当免做分镜的默认许可。
- 每批交付正文之外，还附建议删减项、逻辑/动机风险、最值得强化的冲突与卡点备选，供人选择；不把第一版当终版。
- 单镜通过后仍按剧本顺序连续播放全体场景，专查相邻镜头接起后才出现的节奏断点与缺失叙事拍。
- 系列声音资产除音色来源外，还要版本化记录表达强度、情绪、语速、音高与音量；有意变化另记状态，不凭耳朵重建旧配置。
- 连续性终检抽取相邻两集做盲测：不看标题时，仍应能从固定声音、视觉语言、结构节奏或角色认出同一系列。
