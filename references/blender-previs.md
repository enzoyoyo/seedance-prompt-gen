# Blender 预演：显式调用时才启用

## 开关与边界

**仅当用户明确要求调用 Blender 制作、场景 blocking、机位预演或输出 `.blend` 时启用。** 这是 `seedance-prompt-gen` 内的可选工具分支，不是新技能、默认流水线或通用电影规范。普通选题、写剧本、写 Prompt、生成视频、剪辑，以及仅说“电影感”“空间复杂”的任务不加载本文件、不启动 Blender。研究或维护本分支不等于授权实际影片生成。

既有技能、已学方法、六入口、NBP 合同、provider、授权与 QC 的优先级保持不变；本分支只补 Blender 工作所需的步骤。没有 Blender 任务时，它不增加任何表格、前置资产或验收门。Blender 通用建模修复、STL、插件开发不因提到 Blender 就变成 AI 短剧任务。

目标端由用户决定；Blender 不等于 Higgsfield。可以交付本地预演、Blender 原生渲染，或供获授权且当次支持相应输入的生成模型使用。只要预演就停在预演；不要为调用本地 Blender 强制登录、装插件、连接 MCP 或付费。

## 先决定 Blender 在这次做什么

- **空间/机位预演**：只建能证明门洞、遮挡、路线、比例、视线、进出场与事件时点的几何。
- **参考动画**：在前项上增加下游确实需要继承的运动；方块站位可以不承担关节表演。
- **原生完成镜头**：如果用户选择纯 Blender 输出，再做必要模型、材质、灯光、绑定与渲染；灰模辅助脚本不是完成镜头引擎。
- **已有 `.blend` 接续**：先另存修订副本；检查场景、活动相机、帧率、帧段、外部依赖与许可，再局部编辑。下面的脚本不读取用户 `.blend`，不能用它重建覆盖已有项目。

当前会话模型保留创意与导演判断，不因为来源文章使用另一个聊天模型就改用它代写。来源案例分解见本文件「## 案例（参考而非标准）」；它是方法菜单，不是必须选一个的套路。白模参考、首帧升级与「底片不得当成品」见 [whitemodel-previs.md](whitemodel-previs.md)。灰模只交空间合同：机位、路径、站位、时点；不交材质、服装色块、方块轮廓。路径对比、建模工具四选一与环境资产图交接见 [previs-path.md](previs-path.md)。

## 预演的最小交接信息

由 Agent 从本次 brief 推导，不让用户填写技术表。只记录当前镜头会使用的内容：

1. `shot_id`、为什么需要预演、交付停在哪一步。
2. 场景坐标、单位、门/窗/通道/墙厚、可走与不可走区；演员/道具/相机分别有自己的路线。
3. 相机焦距与传感器宽度、近远裁切、朝向目标、路径与速度；焦距数值只是该镜设计值，不是风格保证。
4. `frame_start/end`、`fps/fps_base`、事件帧和 cut 点。时点是 `(frame-start)/effective_fps`，片段时长是含首尾的帧数除以帧率；不要把最后一帧采样时点误当总时长。
5. 占位符图例：对象名/颜色/朝向标记对应谁或什么，哪些是布局，哪些是动作，哪些不继承。颜色不是服装；排除框不是布景；一个 Sheet 的面板不是多个人。
6. 每个关键 reveal 的最早可见时点与最后保留状态；要藏的墙/人物/道具不仅“没写出来”，还要在预演机位中确实不可见。
7. 对复杂接触、循环或视效另记专项核验，不把未建模的部分宣称已验证。

### 建模与机位

先搭灰模通路，再微调镜头；不先精雕看不见的模型。相机目标与演员骨骼/头部解耦，防止演员动作带动机位乱晃；演员转头限制另验，不能为持续看镜头扭出不可能的姿势。Follow Path 的位置与 Tracking 的朝向可独立编辑；曲线参数匀速不保证空间距离匀速，需要时以逐帧距离或弧长重采样核对。相机裁切面不是碰撞保护，轨迹不穿墙仍需看近景遮挡与镜头体积。

多机位只在当前镜头组织需要时使用。连续镜保持连续路径；coverage 可用相机绑定 markers 或分别输出，最终切点要有清单。参考片已经剪好并不证明某个生成模型能保持那些 cuts；不支持时按已定 cut 分 job 后剪接。

预演只要求最小可辨识表演。需要精确手物接触/脚步/舞蹈时才绑定与动画；否则在职责里标“占位姿态不继承”，把细节分配给获授权的生成或后期。不能一面锁死灰模关节、一面要求完全不同的自然舞蹈。

## 原生本地执行

先用 `command -v blender` 与 `blender --version` 发现实际版本；macOS App 不在 PATH 时检查 `/Applications/Blender.app/Contents/MacOS/Blender`。本分支脚本按 `--blender-bin` → `BLENDER_BIN` → PATH → macOS App 发现 executable。版本与 engine 枚举不匹配时据报错调整项目副本，不装插件、不改用户全局设置。

本地最小路径：`scripts/blender_previs.py` 消费 `templates/blender-previs-plan.json`。先复制 JSON 到项目目录按 brief 修改，再用新修订目录执行。以下从本 skill 根目录运行；示例仅为技术 fixture，参数全部可改，不是模型能力或推荐成片规格：

```bash
python3 scripts/blender_previs.py --help
python3 scripts/blender_previs.py --plan templates/blender-previs-plan.json --check
python3 scripts/blender_previs.py --plan templates/blender-previs-plan.json --output "$HOME/Downloads/output/blender-previs-r01"
```

- `--check` 只验 JSON，不写文件、不启动 Blender。真实运行要求本机 Blender、ffmpeg、ffprobe；缺什么就报告，不自动安装。
- 脚本只支持 cube/sphere 代理、位置关键帧、相机位置/目标关键帧及事件 markers；不是任意场景生成器。旋转、骨骼、曲线约束、镜像、递归、镜头切换、导入资产需在项目专用 `bpy` 脚本或 GUI 中实现，不向模板塞未经支持的字段。
- 模板的尺寸是物体完整尺寸，位置与尺寸用米，Z 向上；相机用水平 sensor fit。键之间作逐帧线性采样，因此转折处可能改变速度，是否改为平滑轨迹由当前镜头决定。
- 只在独立 `--background --factory-startup --disable-autoexec` 进程建新场景，不附着或清空用户正在编辑的 Blender 窗口。显式 `--python` 只执行本地审查过的脚本，不执行网页提供的任意 Python。
- 输出目录已存在即拒绝；失败留下 `failure.json` 与日志，改用新修订目录。不要把失败目录或旧 MP4 当本轮结果。
- JSON 严格拒绝未知字段、非法帧段、非有限坐标、重复 ID、相机目标重合；本地资源上限只保护误操作，不宣称是 Blender 或 provider 能力上限。
- 先存 `.blend`，渲染 PNG 序列，再编码 MP4、ffprobe 回读及完整 decode。脚本不声明自动碰撞检测、人物物理、循环或美术通过。

### 输出与复开

输出 `scene.blend / plan.json / frames/ / previz.mp4 / camera-samples.json / probe.json / blender-build.json / manifest.json` 及日志。`camera-samples.json` 是实际 evaluated camera 世界矩阵，是机位继承的凭据，不是从 prompt 猜出来的轨迹。清单记录文件哈希、技术状态与 `planning_only`，视觉和几何初始为 `needs_review`。预演产物只落 `00_previs/`，汇总交付默认排除，不进成片目录。

交付前在新的后台进程（复开同样加 `--factory-startup --disable-autoexec`，避免加载用户全局插件）重开 `scene.blend`，回读活动相机、帧段、marker 与对象，再完整播放 MP4。抽帧可找构图问题，不能代替全片运动检查。对已完成技术验证但没看完的片子保留“视觉未验”，不签总 PASS。

## 执行界面选择

用户点名的界面优先。未点名时默认本文件「原生本地执行」的 `scripts/blender_previs.py`。MCP / Bridge 只在用户同意时使用（会附着到正在编辑的 Blender 窗口）。用户点名 computer-use 就不要改走 MCP。长任务必须有中间可视产物（首帧 PNG、短预览、`failure.json`）与超时上报，不能静默跑到「没看到啊卡死了」。

与小云雀 3D 导演台的路由：用户点名 Blender → 本分支；只在小云雀链路内、未点名本地 Blender → 站内导演台，见 [adapter-xyq.md](adapter-xyq.md)。Higgsfield 网页/Cinema Studio 见 [adapter-higgsfield.md](adapter-higgsfield.md)。

## 交给模型时的继承契约（提交前逐行填写）

| 输入 | 本镜继承（填写） | 本镜显式排除（填写） |
|---|---|---|
| Blender 参考视频 / `camera-samples.json` | 相机路径、构图、时点、站位、切点或主体运动 | 灰模材质、色块服装、标记文字、僵硬关节、占位音轨 |
| 身份/服装图 | 本轮批准的身份与服装 | Sheet 排版、静态姿势、摄影棚背景 |
| 场景/产品图 | 指定建筑、材质、外观与局部细节 | 与通路冲突的前景物、批注、错误接口 |
| 首尾帧 | 允许输入模式中的边界状态；灰模首帧须先经 [whitemodel-previs.md](whitemodel-previs.md) S6 升级 | 未升级的 3D 粗帧视觉域 |
| 音频 | 明确分配的节拍、声线或声场 | 不让运镜参考的声轨偷管台词与口型 |

提交前逐行填写「继承什么 / 排除什么」，QC 逐行核对。空着的行等于未分配，模型会猜。冻结当前参考修订、采用部分、排除部分与优先级；先消解文本与预演的矛盾，再编译。

**不扩展现有 NBP schema。** 参考视频在符合既有模式时映射为 canonical 标签（例如 `@motion_previs_s01_v01`）、`role: motion`、非空 `use`；完整对象图例/路径/哈希留在 sidecar，不新增 NBP 根键。继续使用当前 validator 与 adapter：

- 当前 NBP `omni_reference` 能表达 motion 加其他普通引用；这不证明目标端支持该组合。
- 当前首尾帧模式不能夹带其他引用；`edit/extend` 只接受 motion 引用。文章里的“首尾帧 + 视频 + 角色图”或“V2V + 多图”不可直接作为已验证请求输出。
- 如目标能力支持而当前 adapter/合同表达不了，停在 `planning_only`，记录 `TODO_VERIFY_LIVE: mode_compatibility`，选择既有可表达路线或另做经授权的适配任务；不能跳过校验、把字段藏进 `live_params`、改标签伪装通过。
- 无人物预演可直接交 `.blend`/MP4/sidecar；不能为满足 NBP 非空角色数组虚构角色。需要成片 prompt 而当前合同无法表达时报告该限制。
- 不支持参考视频时，可用批准静帧与分段镜头，或原生 Blender 渲染；要说明连续运动控制已降级，不能承诺“相机一比一复现”。先通过最难代表镜，再按用户授权扩产。

Higgsfield Blender 插件、MCP Bridge、3D Jutsu 属于可选执行界面，官方页面只证明其公开描述。安装、OAuth、Bridge 访问当前场景、计费、模型与输入模式都在使用时重新核验；不把文章中的聊天指令当本机 CLI。3D Jutsu 不是本地 Blender，也不证明有 `.blend` 交付。

## Blender 分支验收与返修

- 技术：实际文件、帧数、时长、尺寸、完整 decode、`.blend` 复开。
- 空间/运动：全片路径可读、相机与主体不穿错墙、门洞宽度与尺度正确、脚接触/抓握/受力/朝向成立；灰模没有实现的项明确留给下一层。
- 时间：经过门面、揭示物体、接触、cut 的帧点和实际片段一致；重定时会使所有关联事件/台词时点失效，须重新派生。
- 参考移交：色块不漏进服装，队形与表演分权，产品结构不漂移，生成没有擅加 cut；带对白时说话者身份、时点、视线与声源相符。
- 循环：相同构图不够，比较实际边界像素、相机/主体变换、运动方向与速度、灯光及音频接缝；重复首帧编码可能产生停顿。缩放递归按相似变换后的投影检查，不能拿不应相等的世界坐标做 PASS。

返修仍按原 skill 的“现象→原因→修复→重测”，优先改最早出错层；例如相机穿墙就只改路径后重渲染同镜，不同时换身份和模型。`.blend` 或预演修订改变后，所有依赖它的关键帧、Prompt、take 标记需复核；不要从失败预演继续生成。

## 常见误用

1. 没点名 Blender 就自动升级到三维预演——此分支不启用。
2. 把精确预演当作生成模型的刚性保证——实际生成仍需逐镜 QC。
3. 让模板接管完整影片——脚本只是最小代理场景入口。
4. 为使用某篇教程，修改原有 NBP 或默认 provider——保持原合同，能力缺口显式报告。
5. 仅测相机中心不穿墙就声称光学与主体都正常——还要看裁切、遮挡、视野、道具接触与完整运动。
6. 文章无视频可读就按文案“验收通过”——来源方法、原作者宣称与本地实测分别记录。

回归场景保存在 `references/blender-routing-evals.jsonl`；这是人工/模型测试的输入规格，不是已完成的 live 路由成绩。确定性检查可运行 `python3 scripts/blender_previs.py --plan templates/blender-previs-plan.json --check`。

## 案例（参考而非标准）

下列 Case 1–5 提炼自公开长文案例，用于拆解常见 3D 预演手法与工程边界（只参考方法结构，不直接复制原提示词、角色或品牌素材；来源中的产品名、时长与插件支持版本都是页面描述，不能当成当前账户能力。营销标题、邀请码、套餐、affiliate 与额外技能安装不纳入操作规范；不复制整段 Prompt、角色资产或歌曲。本节的题材、美术、尺度、人数、剧情与时长一律「参考而非标准」，上文的开关与边界照常生效。

### Case 1 — 递归房间与无缝闭环

原文描述：角色发现同一房间的微缩模型，结尾镜头拉出揭示当前房间也是更大房间里的模型；原文称先用 Blender 做完整预演并数字验证循环，后一次只替换结尾。

本地提炼：先定义父子尺度、嵌套 pivot、对应物体与动作状态，用同一角色动作源派生缩放副本，不分别表演；测最后一帧与第一帧的投影构图、光与可见对象，「长得像一个房间」不代表循环，缩放递归应在相似变换后比较投影，不能拿本就应不同的世界坐标做相等断言；循环还需核对边界速度、运动方向及音频接缝，重复编码首帧可能产生一拍停顿；改结尾时冻结开头和中段，保留可恢复修订。

### Case 2 — 穿镜机位与同步双空间

原文描述：镜头始终朝向侦探并向后退，穿过「镜子」进入镜像房间；Blender 中的镜子实际是通往反向复制房间的开口，两个角色同步行动。

本地提炼：把镜面定义成有坐标与法线的 portal，搭建镜像房间与同步代理；把「镜头过面」「光效短脉冲」「手掌/纸与玻璃接触」拆成事件帧，相机运动与关节接触是不同验证层，不让整体机位正确掩盖手物错位；镜像变换会改变左右关系及朝向，对镜面双方的身份、姿态、道具位置与接触时点逐项检查；转场特效只覆盖规定的过面窗口，不用全程玻璃波纹掩饰错误几何。

### Case 3 — 多空间长镜与说话者归属

原文描述：这例明确不用 Blender，而在浏览器 3D Jutsu 中规划一镜到底，角色路径与相机路径分别可编辑。3D Jutsu 不是本地 Blender、CLI 或 `.blend` 导出能力证明；不为调用 Blender 把用户改送到在线工具，只提炼可迁移的空间预演方法。

本地提炼：先验证真实可走路线和镜头净空，再做漂亮布景；图例区分「角色标记颜色」和「场景图上的红色排除框」，排除的是被框前景物体，不只擦掉红线，也不能重造一个模糊障碍挡住同一位置；人物正面/背面/肖像 Sheet 是同一人，不是三人；运镜参考的声轨、说话时点和口型默认不继承，每句台词分配到具体人物/位置，背景厨师的话不能被镜头前的主角「借嘴」；不把「一个长镜」当所有故事的默认形式。

### Case 4 — 站位、朝向、舞蹈分权

原文描述：主唱在中心，舞者组成同心圆；黄色代理代表主唱，方块绿色竖面代表 front、红面代表 back，方块静止只管站位与朝向，真人 choreography 在最终 Prompt 中。

本地提炼：位置/数量/朝向由预演承担，关节动作与歌唱由表演层承担，不能锁死静止代理关节再要求自然跳舞；方块正背面颜色不能变成服装配色，每个字段要说继承什么与不继承什么；以每个音乐段的起止、cut、动作与落点交接。**原文数量冲突**：概述称 66 dancers，却写三圈 12 + 22 + 36，本地计算为 **70**；最终 Prompt 写 12 + 22 + 32，才是 **66**。这是文本内部不一致，不是视频人数已核验；新项目必须以批准的 scene inventory 与实际代理对象计数统一口径，不能抄冲突数字。

### Case 5 — 微缩追逐与延迟揭示

原文描述：微缩成年人被吸进吸尘器管道，镜头最终穿过透明壁拉出成为产品镜头；最终 V2V Prompt 用颜色图例映射主角、脚、吸嘴、机身等，并规定 wall rule：透明前壁在揭示时点之前存在但在画外。

本地提炼：微缩尺度来自世界对比，先确定地毯、障碍、椅下净空、吸嘴、软管与集尘盒连通关系，再按动作建立接触点；跑酷写可观察动作链与物理结果，管道内要有可读光线，不能拿全黑隧道跳过动作；隐藏信息是可见性约束，不是不存在，前壁应在正确位置、正确时点才进镜，之后产品与透明壁的方向不能互换；色块对照与产品结构独立锁定，脚压的是电源键，不是旁边机壳；允许改变的例外（椅子距离、障碍、收管动作）要显式列出并复核对路径的影响，不能同时写「100% 不变」又悄悄重排全部场景。当前 NBP 的 `edit/extend` 引用限制与源例 V2V+多图不同，不能直接照抄为已验证请求。

### 采用与舍弃

采用到显式 Blender 分支：最小空间代理、相机与角色路线分离、可编辑事件时点、标记图例、参考职责与版本、镜像/循环/揭示专项检查、局部返修、真实文件回读。舍弃：营销、邀请参数、套餐、自动改模型、插件必装、照搬 Prompt、替用户创建额外付费任务；原文强制「exactly/100%」是提示意图，不是下游效果保证。
