# 热点雷达：选题脑暴的搜源、拆解与反固化

用户说「脑暴／结合热点／最近什么火」时才走这条分支。默认路径（用户已给方向且没说脑暴或热点）行为不变，不得因为「顺手」发起联网搜源。本文件只加一个前置修饰，不新开 Lane：命中后仍停在文本，不进分集、资产、分镜或 Prompt。

## 开关与两个子形态

触发词（任一即触发）：脑暴、脑暴选题、帮我想选题、想不到选题、选题不确定、不知道拍什么、没想法、没有想法、结合热点、最近什么火、当下热点、时事热点、社会舆论、大家现在爱看什么。

| 子形态 | 命中条件 | 产物 |
|---|---|---|
| 开放雷达 | 用户没有可用创意材料（题材／人物／前提／大纲／剧本皆无） | 全市场雷达 → `### 脑暴 pitch` 下 2–3 个 pitch，沿用既有六项格式 |
| 锚定雷达 | 用户已给方向，且说了脑暴或热点 | 雷达只围绕该方向与相邻方向 → `## 张力门诊断` 的「升级选项」与「共鸣加固」 |

锚定雷达**不替换用户方向**，与 SKILL.md「创意模式」一致；只有该方向本身不成立时才按「剧本接单两态」给替代方向。接单问题、默认假设、pitch 六项、张力门诊断表头的逐字写法一律以 `script-intake-contract.md` 与 SKILL.md 为准，本文件不重定义。

## 第 0 步：探测搜源工具

```bash
python3 scripts/list_research_tools.py
python3 scripts/list_research_tools.py --json   # 供宿主读取
```

原样打印脚本输出的 `### 搜源工具` 表。脚本是 stdlib-only、不联网、不执行被探测的 CLI，凭证只报名字与 present/missing，绝不回显值。

- `any_available` 为 false（全部不可用）→ 整段标 `RESEARCH_SKIPPED`，回落到默认接单路径，并在 `### 默认假设` 内写一行「本轮未联网，pitch 无实时依据」。
- 部分可用 → 用可用的，缺掉的维度逐条标 `Dn: RESEARCH_SKIPPED`。
- 宿主原生检索一行固定「由宿主判断」，它耗当前模型额度，脑暴模式默认排在本机 CLI 之后。

## 第 1 步：五维搜源

查询词由本轮 brief 加当日日期生成，不预填结论。下表的平台名单只是**检索清单**，不是结论，也不是排名；brief 指定平台时只查该平台。**每个维度单独发一次调用**：实测把五维合并成一问会让 grok 停在 `max turns reached`，拆成单维度 7 轮就收敛。

| 维度 | 问什么 | 首选工具（非当前模型） |
|---|---|---|
| D1 平台与分类榜 | 近 30 天（可改）各短剧平台最热分类、方向与播放量样本：抖音、红果、快手、微信小程序微短剧、B站、小红书、TikTok、YouTube Shorts、ReelShort／DramaBox | grok CLI、Hermes、agent-reach／opencli |
| D2 受众分层 | 年轻人（18–30）与中年（35–55）分别在哪些平台看哪些分类、为何看；平台官方数据报告 > 行业报告 > 评论区观察 | grok CLI、Hermes |
| D3 AI 短剧专项 | AI 短剧热门案例、平台扶持／榜单／征集、观众对 AI 短剧的接受点与吐槽点 | grok CLI、Hermes、agent-reach |
| D4 时事热点与社会舆论 | 近 30 天（可改）微博、知乎、小红书、X 的热议话题与新闻里的公共情绪（经济、就业、婚恋、代际、AI 焦虑、平台事件等） | grok CLI、Hermes |
| D5 跨领域共鸣点 | 同窗口内综艺、游戏、音乐、梗、播客、网文、影视里正在被反复引用的情绪与桥段类型 | grok CLI、Hermes、agent-reach |

每条结果进证据台账，字段沿用 `live-trend-intelligence.md` 的 ledger：`claim_id`（本分支统一 `R-01`、`R-02`…）、`evidence_class`、`source_url`、`published_at`、`captured_at`、`platform / region / language`、what was directly observed、decision affected。

- 数字（播放量、榜单名次、人群占比）必须与 URL＋日期同行，否则该处写 `TODO_VERIFY_LIVE`；模型回答只是 lead，不是证据。
- 采样停止规则沿用 `live-trend-intelligence.md` 的 “Sample until the mechanism stabilizes”，不硬编样本数；但至少覆盖两类受众、两个以上平台、一条以上 D5 跨领域来源，缺哪项就写明缺口。
- 榜单、平台规则、人群比例、算法权重一律不写进本文件或任何 reference，它们是当轮证据，不是规则。

## 第 2 步：逐样本拆解（`### 爆款逻辑拆解`）

每个样本或样本簇一行，列固定：

```text
| claim_id | 样本（平台/受众） | 热度证据 | 观众处境与共同认知 | 情绪承诺（观众在等什么） | 最早可读时刻机制 | 跨领域共鸣点 | 为什么是现在（时代因素） | 与饱和版本的距离 | 风险与衰减预期 |
```

「跨领域共鸣点」列回答「从全网其他方向找共鸣点」；「为什么是现在」列回答「它为什么会爆、选题优势在哪、大家喜欢的理由是什么」。

**逐帧行（可选）**：样本视频可合法公开获取时，用 `yt-dlp` 下载到临时目录，用 `ffmpeg` 抽 0–2 s、钩子、转折、结尾关键帧，交 `agy -p "<问题>" --model "${AGY_MODEL:-gemini-2.5-pro}" --effort high --add-dir <目录>` 读第一帧的关系、争夺物与第一个不可逆动作，方法沿用 `trend-research.md` 的「0–2 秒钩子：研究第一帧，不研究口号」。不可获取时该样本标 `FRAME_ANALYSIS_SKIPPED`，只用文字、评论与字幕证据，不用想象顶替。

学机制，**不抄 IP**：沿用 `trend-research.md` 的同名小节，不记录可复制的人物组合、标志性台词、道具与镜头顺序。

拆解草表可由 Hermes 或 grok 先产出；**pitch 引用到的 claim 必须由当前模型打开原始 URL 核验**，未核验的只能作 lead，不得进 pitch。

## 第 3 步：选题分析（`### 选题分析`）

每个候选方向写四行：

1. 共鸣点——引用 `claim_id`，指明是哪一类观众的哪一种处境。
2. 机制——观众为何愿意继续看，落到 `dramatic-tension-engine.md` 的八行语言，不用题材词代替。
3. 为什么是现在——时代因素、事件窗口或情绪拐点，引用 `claim_id`。
4. 为什么适合 AI 短剧——AI 能生成而实拍难或贵的画面、形式优势，以及本轮资源匹配度。

候选若切入**「赛博微综艺 / 规则真人秀」**方向：共鸣点落到大众心智已有的经典模式（如身份逆差改造、极限生存淘汰、职场整顿）；机制落到「规则约束 + 轮次变量递进 + 淘汰惩罚」；形式优势写清「超现实大场面零实拍成本、虚拟角色无真人伦理争议、Confessional 小黑屋与演播室机位保真可控、天然广告赞助位」。

## 第 4 步：反固化检查（`### 反固化检查`）

逐方向打勾，任一不过就换方向：

- (a) 依据的 claim 其 `captured_at` 在 30 天内（可改）；
- (b) 有一句「为什么是现在」；若本质是持久人性模式，必须明写「持久模式」并给一个当下变体；
- (c) 至少一个方向来自 D5 跨领域共鸣，而不是短剧榜单本身；
- (d) 去掉热点标签后张力仍成立——`open-creative-director.md` 的 swap test；
- (e) 不复制 IP 人物、世界观、桥段、台词；
- (f) 用户给了排除清单或上次方向时，逐条声明本轮与之不同之处；
- (g) 对照 `open-creative-director.md` 的 model-default test：撞上模型惯用的人名或前提时，写出本方向和它的区别；写不出就换方向。

热点会变，所以这一步检查的是「依据是否还新」与「张力是否独立于热点」两件事，不是固定几个方向的清单。

## 第 5 步：回到既有接单契约

开放雷达：`### 接单问题`（≤2，逐字标题；无阻塞项写「无阻塞项，按下方默认假设继续」）→ `### 默认假设` → `### 脑暴 pitch`（`#### Pitch N`，六项逐字）。每个 pitch 末尾加一行 `热点依据：R-xx`，列出该 pitch 实际引用的 claim_id（与 `validate_script_gate.py --mode intake` 校验器兼容）。

锚定雷达：改走 `## 张力门诊断` 表，表头与八行逐字不变，「升级选项」列内的每个选项后括注引用的 claim_id。

## 输出契约（第一条回复的节顺序，标题逐字）

```text
### 搜源工具        ← 脚本原样输出（或 RESEARCH_SKIPPED 说明）
### 热点雷达        ← 采样范围行（captured_at、平台、受众、时间窗）+ 证据台账，每行含 claim_id、URL、日期
### 爆款逻辑拆解    ← 第 2 步固定列
### 选题分析        ← 第 3 步
### 反固化检查      ← 第 4 步
### 接单问题 / ### 默认假设 / ### 脑暴 pitch   ← 既有契约不变；锚定雷达改为 ## 张力门诊断
```

## 校验器兼容硬约束（以 `scripts/validate_script_gate.py` 的实际行为为准）

- `MARKER_PREFIXES` 含「脑暴」「标题候选」「接单问题」「张力门」等，`### 脑暴 pitch` 是 pitch 区间的起点：新节标题**不得以「脑暴」开头**，只有既有的 `### 脑暴 pitch` 例外；正文里也不要让任何一行以「脑暴」两字开头。
- 非 pitch 节内任何独立句**不以问号结尾**，包括表格单元格内的行尾（写作约定，校验器不检查；只有 `### 接单问题` 节里的编号问句按既有契约保留问号）。
- `PITCH_NAME_RE` 匹配 `pitch 1`、「方案N／点子N／提案N」：雷达与拆解节内**不得**用这些词命名研究样本，用 `R-01`、「样本 A」等。
- pitch 区间内不得出现与 pitch 无关的编号行（`1.`／`-`／`*`），否则会被计成新的 pitch 块。
- pitch 数量 2–3、`### 接单问题` ≤2 条编号行的计数规则不变；第一条回复不得含剧本正文。

## 运行时模型分工

搜源与抓取优先交给独立检索工具分工执行，避免耗尽当前会话模型额度：

| 动作 | 交给谁 |
|---|---|
| 搜源、网页抓取、样本下载、逐帧分析、拆解草表 | `grok -p`、`hermes chat -q ... --oneshot -Q -t web`、`agent-reach`／`opencli`、`yt-dlp`、`ffmpeg`、`agy`；都不耗当前模型额度 |
| 补位检索 | 宿主原生 WebSearch／WebFetch；耗当前模型额度，脑暴模式默认排后 |
| 打开 pitch 引用的原始 URL 做核验、写 `### 选题分析`、`### 反固化检查`、pitch 与诊断 | 当前会话模型；最终创作判断不外包，与 SKILL.md 硬边界一致 |

不新增任何常驻后台、MCP 服务或向量库；命令都是一次性 CLI 调用。

## 外部检索 CLI 调用要点

| 命令用法 | 说明 |
|---|---|
| `grok -p "<单维度提示>" --output-format json --max-turns 40` | **必须按 D1–D5 维度拆开逐条提问**；若把五维合为一问，并行检索线容易耗尽轮次 |
| `hermes chat --query-file <file> --oneshot -Q -t web --max-turns 8 --run-budget 420` | 务必加 `-t web` 限定检索工具集，避免默认全量工具集撑大上下文导致超时 |
| `agent-reach doctor --json` / `python3 scripts/list_research_tools.py` | 开搜前检查本机可用检索工具与登录态 |
| `agy -p ... --model "${AGY_MODEL:-gemini-2.5-pro}" --effort high --add-dir <目录>` | 逐帧读取样片关键帧，不直接替代完整回放判断 |

## 不做

- 不改默认路径的既有规则、格式与计数；不改 `validate_script_gate.py` 的语义。
- 不硬编榜单、平台规则、人群比例、算法权重；不把训练记忆里的「热门题材」写成结论。
- 不触碰 `2026-platform-evidence.md`（由 `platform-evidence-ledger.jsonl` 哈希校验锁定）。
- 不把跨会话无关题材写进雷达或 pitch，严格遵守主入口「上下文隔离原则」。
- 争议、擦边、真实人物与 AIGC 披露仍按 `platform-risk-and-compliance.md`；不把限流或删除风险伪装成流量技巧。
