# Keyframe Assets

## 边界

本文件规定角色、道具与关键帧资产如何生成和冻结；资产的 canonical ID、批准状态、版本替换与 continuity in/out 仍以 [continuity-storyboard.md 的“角色定型”](continuity-storyboard.md#角色定型) 和 [状态交接](continuity-storyboard.md#状态交接) 为准。不要在这里重建 shot contract。

## 角色资产链：Identity / Outfit → Minimum sufficient view set

先按复用度、漂移风险和下游镜头判断资产分辨率。可辨认、会复用的角色先批准身份，再把服装生成在已锁身份上；一次性背影、不可辨认群众或只承担轮廓职责的角色，不为完成仪式强建 face lock、outfit 与完整 Sheet。

```text
required_views / required_details / downstream_shots / minimum_pixel_readability
→ 选择最小身份与服装真源
→ 按镜头需要派生单图、分图、2/3/6-panel 或不制表
```

对需要身份与服装双锁的角色，`face lock → outfit baseline` 的依赖顺序仍是硬门；可选 view set 从已批准真源派生，不反过来替代身份锚。

角色资产只覆盖确需身份和服装连续性的角色；固定卡优先于逐镜复述。身份锚只锁脸部结构、表情方式与体态，服装、配饰和反复道具另设锚；管线前置物缺失时回退补齐，不越级生成。

角色资产来源三选一：手写提示词生成，主角默认走这条；从剧本自动识别后人工修，用于配角与阶段形象；预设库现成角色，用于配角与群像，取用前核对授权、地区外观与年代。主角一律手动锁定，识别结果与库内角色都要人工修过再批准。同一角色的不同年龄或剧情阶段各建一组版本资产，共享身份锚，服装与状态另设锚，不用一张参考图跨阶段硬撑。可选槽位顺序（不设为门）：身份／年龄／面部特征／身材／发型／衣着／气质／常用表情。

### 1. Face Lock

先冻结脸部骨相、眼距、鼻唇比例、肤色、发际线、发型、永久标记与静止态读数。基准服装保持中性、低信息量，避免造型抢走身份权重。

改变发色/发型、常驻妆容、面部疤痕、纹身或穿孔等“静止时可见”的永久特征，必须生成新 face-lock 版本；不能只在后续 Prompt 中悄悄覆盖。

通过门：单脸清楚、正侧结构相容、无美颜磨皮、无戏剧光污染、无背景语义、可从身份而非服装认出角色。

正典锁定与重锁使用同一件中性无饰基准服装。只有改动会改变静息脸部读法时才重锁；年龄变化从新身份开始，不伪装成旧身份补丁。

### 2. Outfit Baseline

只有 face lock 批准后才上服装。身份参考只负责脸、皮肤、头发和体型；服装参考只负责剪裁、结构、材质与颜色。服装默认一次直接生成在角色身上，让骨骼、姿态、重力和褶皱共同成立，不先在通用模特上做二次合成。

复杂单件被模型简化时，才补无头幽灵假人资产做局部修复。完整态、战损态或换装必须各自成为独立 outfit variant。

通过门：脸未退化；正背剪裁、层级、鞋靴和配件完整；左右不误换；材质不被参考图的无关颜色污染。

每个可见状态都是独立、可回退的 variant，只从已批准资产修改 delta。直接把完整服装建在角色上；仅当某一单件被简化时，才为该件补无形人台修复，其余保持不动。

### 3. Minimum Sufficient View Set

只有下游镜头需要转面、全身比例、服装结构或身份细节时才制表。先列出必须被辨认的视角与细节，再为每个视图保留足够像素；Sheet 不替代独立 face lock。

单图、分开的高清裁切、2-panel、3-panel 与 6-view 都只是布局选择。3-panel 在恰好需要正面、背面或 3/4 与身份近景时可作为像素折中；若只拍正面近景，独立 face anchor 更充分；若只出现一次背影，轮廓/服装参考即可；若镜头需要完整旋转，则独立多图或更多视角可能更合适。

通过门：view set 覆盖实际下游镜头；每个视图达到最低可读像素；同一身份、肤色、比例和服装版本无冲突；没有新增饰品、肢体或背景物。

分格数由下游最低可读像素倒推。三面板中将全身视图去头、另保留四分之三身份近景，只能作为目标模型代表镜验证过的候选策略；对白表情变体同样不是通用必做。多视图默认先用内部自洽的批准服装图，只有脸已软化、遮挡或漂移时才追加身份锚，并声明各自职责。共享身份/服装只写一次，每格只写角度、取景和头部差异；肤色跨脸、背、手臂与手保持同一明度和色相。

悬殊体型除比例描述外，还要在同一地面线上给出可目测的身体地标；地标按角色比例重设，并回到目标镜头像素复核，不把参考图本身当通过证据。

高形变角色可为关键极端状态分别准备清晰端点参考，让变化前后都有身份与结构证据；只保留最小相容集合，并 `TODO_VERIFY_LIVE` 当前图像与视频链路能否共同使用这些输入。

## 双轴分离（按视觉形态适配）

写实真人 Lane 的身份数据资产优先分开两类信息：

- `Axis 1 — Biological realism: ON`：保留毛孔、绒毛、骨相起伏、发丝、织物垂坠和真实材质；
- `Axis 2 — Photographic capture behavior: OFF`：关闭戏剧性主侧光、浅景深、运动模糊、炫光、暗角、色散、雾和强胶片颗粒。

生物真实不是“拍成电影海报”。摄影行为通常在场景关键帧与视频镜头中加入，不烘焙进需要跨场景复用的身份真源。

动画、黏土、剪纸、像素、绘本或其他非写实 Lane 不强开 biological realism；改为冻结该介质真正需要的轮廓、拓扑、线条、色块、材质和比例不变量。若摄影光、颗粒或特定介质痕迹本来就是角色设计的一部分，可以有意识保留，并在资产职责中声明，不套写实双轴。

## 中性无影底板

角色、服装、角色表和道具定型优先使用不携带场景语义、方向性光污染或复杂投影的中性底板与漫射平光。18% 中性灰、白底、透明／抠图结果或其他干净背景都只是候选实现；按目标生图模型、肤色／服装分离度、抠图需求和下游测试选择，不把某个灰度写成跨模型标准。

目标是让身份／几何资产尽量少携带不可逆的场景光信息，使下游镜头能重新着色，并减少高反差边缘的光晕与抖动。若目标模型在纯平光下损失脸部结构或材质辨识，可保留轻微、无强方向性的塑形光，并用代表镜比较下游一致性。

中灰不是默认值。把背景写成不参与受光、投影或地平线的可控色场，再由主体分离度、抠图和代表镜选择灰、白、透明或其他方案。对目标模型可能把 `studio`、顶灯或轮廓光画进资产的行为，只按实测删除对应词；道具保持独立，不烘焙进手。

## 对白关键帧：按口型管线选择起始嘴型

当对白片段以一张静帧直接启动、且当前口型管线从中性基线更稳定时，优先使用自然闭合、放松、无露齿笑的嘴型，让眼神和下颚保持可启动状态。若动作正从上一镜连续接力、首音素需要预备口型，或实测模型从其他嘴型更稳定，则按时间锚与真实前态选择，不把中性闭唇写成普适起始帧。

需要情绪爆发时，把变化写入动作时序，不把终态表情烘焙到起始帧。

## 条件化静帧中继

当下一段是 `continuous_time`，或确实需要继承上一段可见状态时，从前一镜通过 QC 的实际输出中选择身份、手部、道具、光线与动作余势最稳定的一帧，登记为 `approved relay frame`。`editorial_cut` 只继承必要事实并按新镜头重新构图，不为仪式机械吃尾帧。

- 中继帧必须来自通过镜头，不从失败 take 截取；
- 中继负责当下状态，face lock／identity anchor 仍负责身份；
- 截帧若有运动模糊、闭眼、口型半开或遮挡，不因“最接近结尾”而批准；
- 没有合格帧时回到源资产或重抽当前镜头，不能把缺陷传下去。

跨批次只锁身份时，可选上一批最清晰、最像的通过帧；连续时间仍必须用真实末态。两类锚点不得混用。

## 首尾关键帧

首尾帧是可选输入模式，不是每镜必做。选择首尾帧或连续插值时，首帧锁定动作起因、站位、屏幕方向和可见状态；尾帧锁定动作完成后的稳定姿势、道具位置和可剪辑 hold。此时两帧必须能由一条连续物理路径连接，焦段感、光源方向和场景几何相容。

状态突变、换装、严重损伤或跨时空切换不能假装成普通插值；拆镜头并切换批准 variant。

转场用匹配构图、遮挡、甩镜落点、白场/黑场等明确边界；循环镜头让尾帧能物理上回到首帧。

状态变化与位移若互相污染，拆成先改状态、再做移动的两个事件。首帧必须是含空间、站位与当前道具状态的场景时刻，不拿角色肖像代替。目标模型实测能继承静帧光学或曝光时，可把难守的光学/暗度锁进底板；否则保留在镜头控制层。首尾帧入口仍只在两端物理可达时使用。

## 道具资产：最小充分视图与局部标注

先从实际镜头列出道具会出现的面、抓握方式、交互点和状态。只有反复出现、会完整翻转或确实需要全方向精确抓握时才制作正交六视图；其他道具只做足以覆盖下游镜头的视角。记录比例锚点、材质、接缝、开关、可动件和初始状态；只有镜头会展示内部结构时才补 exploded view。

需要模型修改或触碰某个局部时，在副本上用单一高饱和红箭头精准指向交互点，并在文字中命名该部件和动作。箭头是操作标注，不进入 canonical clean asset；生成后检查箭头或红色残影没有被画进成片。

## 参考图职责与预算

一个参考承担小而相容、可独立验收的职责集合：face lock 锁身份，outfit 锁穿着，prop sheet 锁道具，location plate 锁空间，style ref 锁色板/介质，relay frame 锁当前状态。职责冲突、注意力竞争或超出 live 槽位时再拆；不要把角色、服装、道具和场景合成一张万能图。

参考图数量、分辨率和槽位属于 provider 易变参数：快照 2026-08-24，生成前读取 live schema/UI/CLI 校验；默认 14 天过期。使用最小有效集合；更多参考可能造成权重冲突和平均脸。

板阶段锁身份、地点、构图和节拍，视频阶段再设运镜、光学与运动；两阶段传递批准帧，不用重述文字重新发明。空间定位图只管相对位置，不管动作；多人镜可分别用身份、环境与定位职责，但实际槽位和映射查 live schema。每条参考在文本中写清「管什么/不管什么」。地点板采用能证明纵深的角度与单一光逻辑，只在代表镜需要时补更多方向，不把个案角度当默认。

## 资产 ID 与批准门

建议稳定命名：

```text
char-mira-face-v01
outfit-mira-courier-intact-v01
sheet-mira-courier-v01
prop-brass-key-v02
frame-s03-qc-relay-v01
```

状态只允许 `candidate → approved → superseded/rejected`。下游 Prompt 只能引用 `approved`；替换资产时升级版本并标旧版 superseded，不能覆盖原文件。编译为 `@` 标签的方法见 [prompt-compiler.md](prompt-compiler.md#资产-id-与标签协议)。

角色规格与服装方案先在文字阶段批准，再花费生成。任何 delta 型资产提示词同时写变更项与身份防火墙；不重复一套新身份，只列必须保持的骨相、肤色、体型与永久标记。

**AI 短剧前置选图硬门**：先过 `00_previs/` 白模门定空间，由选定白模板旁路 `.blocking.json` 自动推导每名非群演（非 `"extra": true`）角色的 `required_views`（`front` 正面并上机位实际拍到的 `three_quarter`／`profile`／`back`；豁免白模或无旁路工具的场景退回 `front`+至少一非正面；板上角色 id 与身份门角色 id 必须一致），再只为所需视角与主要场景空场主景板（master location plate）备好候选，运行 `drama_setup.py present --gate identity` 生成烧入确认码的决策图交用户看并停下（确认码只属用户本人，Agent 禁读图、转述或代填；属防随手代填摩擦，非密码学证明），待用户回复选项与确认码后用 `drama_setup.py identity --char-view ... --scene-ref ...` 锁入清单；中途换图由 `drama_setup.py impact` 追踪受影响镜头。

## 交付检查

- 需要身份与服装双锁的角色，face lock、outfit 是否按依赖顺序批准？
- 写实 Lane 是否按需要分离生物／材质真实与摄影行为；非写实 Lane 是否冻结自身介质不变量？底板是否经目标模型测试、且没有无意场景污染？
- view requirement manifest 是否来自实际镜头；所选单图/分图/panel 是否最小充分且像素可读？
- 对白起始嘴型是否与当前口型管线、首音素和真实前态相容？
- relay frame 是否来自真实通过 QC 的 take？
- 道具是否具备镜头实际所需视角、比例，以及需要局部操作时的干净／标注双版本？
- 所有下游引用是否指向当前 approved 版本？

生图默认格式和示例见 [prompt-compiler.md](prompt-compiler.md) 与 [nbp-image-prompt.json](../templates/nbp-image-prompt.json)。
