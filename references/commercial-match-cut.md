# 产品变换、成对镜头与匹配剪辑

只在 brief 需要产品变换、两种视觉形态相互切换，或动作接品牌图形时加载。一般产品展示不强加此方法；短剧借用时仍服从批准剧本和连续性。来源提供制作意图，下面的编译与验收方法是本 Skill 的独立归纳，不声称案例已复现。

## 来源与读取边界

[Kaye Creatives《Redbull》](https://higgsfield.ai/@kaye_creatives/blogs/redbull)，页面署期 2026-09-24。方法提炼覆盖角色表、资产入口、Scene 1–4，以及 Scene 5/6 的赛车与骑牛两套提示词和 Recreate 参数；未完整回放成片、未提交生成。正文要求、作者效果宣称、实际像素结果分开记录；本轮证据只覆盖前者。

| 来源位置 | 制作意图的摘要 | 本 Skill 的迁移位置 |
|---|---|---|
| [角色表](https://higgsfield.ai/@kaye_creatives/blogs/redbull#step-1-character-sheet) | 人脸、服装正反面与局部细节分区 | 按镜头歧义取最少视图，遵循 `keyframe-assets.md`；不默认复制固定版式 |
| [Scene 1](https://higgsfield.ai/@kaye_creatives/blogs/redbull#scene-1) | 用受阻动作、运镜揭示和表情变化交代新打算 | 机位揭示什么信息，动作造成什么后果，分开写清 |

| [Scene 4](https://higgsfield.ai/@kaye_creatives/blogs/redbull#scene-4) | 入座、对白、装备和出发串接 | 审计动作负载、道具来去与机位可达性 |

学上述组织方法，不复刻该人物、服装、品牌素材、比赛剧情或镜头顺序。案例的模型选择、时长、画幅、数量和器材名不成为默认值。

资产图的展示约束只作用于资产图：为看清身份而不戴头饰，不等于角色在剧情中不能戴头盔；正反面服装与左右手细节也要区分不变量和当镜状态。按 `references[].use` 继承身份、剪裁与局部特征，舍弃不属于本镜的棚拍背景、展示姿势和光线。

## 产品变化先有因果，再有细节

在批准的 beat 中找清「产品被怎样使用 → 哪个可见接触触发改变 → 改变怎样推进 → 什么完成态证明改变」。每一段特效承担明确状态变化，不能靠电光、烟雾或剪速替代产品介入。

对需要渐进变化的表面，把现有 `continuity` 记录细化到观众能区分的区域：初态、当镜正在改变的区域、已完成区域、触发前沿、尾态。默认已完成区域保持完成；若剧情要求逆转，须有批准的触发与可见过程。不要为了素材丰富度，让每条 macro 都从完全初态重新开始。

宽景和细节镜若表现同一次变化，在 shot list 中标明它们覆盖的**同一源 beat**，说明是替换、插入还是随后事件。剪辑时仅推进一次故事状态；扩大观察同一事件不等于事件再发生。该说明属于拍摄/剪辑备注，不新增 NBP 根键。已有剧本按 `script_ref.source_beats` 对账，后期只保留所需覆盖。

虚构效果与产品功能证明要分开：幻想性的变身可作为形式，但不能被描述为实测功效。每种材质仍应有自己的接触、受力与余势；夸张粒子或火花只在 brief 已确定的风格中使用。

## 成对镜头先设计剪点

两种主体交替出现但不要求真的变成对方时，采用 `editorial_cut`。分别生成能剪接的 A/B 版本；只有 brief 要求连续可见的形变，才设计可达的中间路径。不要用一句“完全相同”替代相互约束。

先写这张最小配对表，只填写影响剪点的项目。它是导演/剪辑记录，**不是新 NBP schema 或提交参数**。

| 项目 | 必须说清 |
|---|---|
| 观看目的 | 这次替换改变观众对力量、关系、形态或结果的哪一种理解 |
| 配对成员 | A/B 的 shot id、批准资产、共用的源 beat；哪些差异有意保留 |
| 主锚点 | 切点最重要的可见点或轮廓，例如眼线、接触点、运动前缘；不要同时要求所有位置都重合 |
| 屏幕几何 | 画幅/裁切、左右方向、锚点位置、主体占幅、接地线/地平线、视角；必要时用归一化画面坐标记，避免跨分辨率误读 |
| 相机与运动 | 相对主体的机位及轨迹、运动方向、切点前后的屏幕速度；背景视差是否需要延续 |
| 动作相位 | 哪个事件发生时可切：接触、压缩、离地、经过地标或视线落定；慢速变化在哪个事件开始和结束 |
| 状态与声桥 | 继承的空间/光线/道具状态；可延续的环境声，以及需随主体替换的声音 |
| 实际选片 | 生成后记录通过 QC 的 source、in/out、切点帧和可用窗口；生成前只能记目标 |

共享的是剪辑关系，主体物理分别写。轮子滚动、悬挂压缩和骑乘步态不能套同一运动文本；要求屏幕运动相近不等于抹掉各自重心、接触顺序和次级摆动。保持角色身份时，角色姿势也必须适应不同支撑关系。

**先解几何矛盾。** 不同真实长度的物体，不能同时强求相同镜头投影条件、物理比例和整身占幅。先决定匹配主锚点、局部轮廓还是整身图形；可有意调整机位距离、焦段感或构图，但要记录由此改变的视差，并看真实配对帧是否可剪。不要拉伸物体、改变角色尺寸或镜像有左右差异的服装来凑齐。

**先测最难的一对。** 选择最依赖轮廓、相位或接触关系的配对，先检查两张关键帧，再按本次执行选择与预算门测试动态素材。需要精确切点或独立修复时拆为独立 pickup；其余组织服从 `cinematic-method-playbook.md` 与 `prompt-compiler.md` 的节拍预算。来源中的完整多镜 montage 是分镜参考，不自动作为一次生成任务。

## 由动作进入品牌图形

先从最终批准图形倒推：需要哪条轮廓、哪个朝向、哪个动作相位和多少画面留白，才能有可读的视觉关联。生成段做到可验收的姿态与干净底板；精确轮廓、图形重组、字标和结尾排版交给确定性后期。只要连续效果能在后期完成，就不要求一次生成同时解决生物运动与精确矢量排版。

不要让抽象“保持 Logo 不变”与“让 Logo 动起来变形”争权：需要动画的是独立图形元素或主体，最终识别标记继承批准的静态素材。表面文字也可使用跟踪合成；保留真实曲率、遮挡、反光和运动模糊，干净底板不等于不受光的平面色块。

若最终姿态在像素中达不到，先调整独立主体姿态或切点；无法连续衔接时，按原 brief 允许的剪辑方式解决，不把失败画面强解释为已经完成的匹配。未批准的形式改变不能静默代替目标。

声音以事件为锚：接触声证明动作，环境底保持空间，主体专属声音随替换变化；慢动作的音高/时长变化、安静收束和音乐进入由剪辑决定。不默认每次画面切换都截断全部声音，也不把案例的无配乐策略扩展成硬规则。参见 `audio-music-ducking.md`。

## 不照抄的源稿问题

以下为公开案例正文与参数面板之间常见的口径冲突，复用方法时须逐项核实对齐：

| 冲突 | 复用前如何处理 |
|---|---|
| 角色表和后续场景的身高设定不同 | 用批准角色资产统一尺度；不任选教程中的一个数字 |
| 多场正文的时长/画幅与 Recreate 参数不一致 | 对齐 `duration.target_s`、分段终点、`aspect_ratio` 与实际提交参数；能力仍标 `TODO_VERIFY_LIVE`，直到执行时核验 |
| Scene 2 已完成变化，Scene 3 又从初态讲同一次变化 | 标为替换/扩展 coverage，或重新安排同一事件的镜头顺序，不能直接当下一事件顺接 |
| Scene 3 的镜头总则与实际宽景出现位置不一致；末滴沿用未在本场登记的机位参考编号 | 逐镜对账，当前场景显式登记素材及 `references[].use`，不跨场猜号 |
| Scene 5 骑牛版要求的人物眼睛特写数量与实际列表不符 | 区分人物眼睛、动物眼睛等主体；以批准 shot list 核对可见次数，不靠总数口号 |
| Scene 6 骑牛版同一参考编号被写成动物资产和最终 Logo | 两种资产使用独立 canonical tag 与绑定；缺少任一资产就标缺失，不伪造引用 |
| 早期场景要求生成精确字标，后期场景又要求留空面给合成 | 统一后期职责，相关镜头都服从同一批准方案 |
| 相同占幅/机位要求与两种主体的尺度关系冲突 | 按主锚点明确图形匹配与物理连续性的取舍，不能同时写互斥要求 |

压缩源稿时按 `prompt-compiler.md` 的外来教程预检处理。重复的大写警告不是更多控制力；保留能指导画面或判失败的条件，其余重复移除。独立编译后仍须读回确认原意，结构校验不负责理解自然语言全部矛盾。

## 实际验收与单变量修复

- **因果/状态**：产品触发、变化前沿、完成态都可见；细节镜不让状态回退，不重复推进同一事件。
- **配对**：并排看切点，再连续播放 A→B；检查锚点跳动、方向、占幅、背景视差、动作相位和声音衔接。相同提示词、种子或时码都不能代替画面匹配。
- **物理**：分别检查 A/B 的受力、支撑、接触与余势；背景应继续存在的运动不能无意冻结，有意的定格另行标注。
- **收尾**：匹配姿态可读，精确标记来自批准素材，过渡和最终 hold 通过实际时间线回放。
- **修复**：按「现象→原因→修复→重测」，只改最早失效的一项，如 `camera` 锚点、`action` 相位或 `references[].use`；单边失败只修该边，保留合格 take，再复核相邻切口。

配对检查纳入现有 `shot-selects` 与 `production-qc.md`，绑定真实文件和选片区间；仍须技术、视觉、brief 分验。本文件与单测通过仅证明方法已接入，不代表新模型已生成成功。
