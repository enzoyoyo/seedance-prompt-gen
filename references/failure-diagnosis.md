# Failure Diagnosis — 生成失败分诊与返工

用途：把剧本到成片的失败先归层，再给出可复测的最小修复动作。
适用条件：已有文本、资产、提示词、生成结果或成片可供比对；无证据时只列待确认。
与相邻文件分界：本文件负责找病与定位；各专项门负责二值验收，adapter 与 live schema 决定当次参数能力。

## 1. 先分诊，不先改稿

五轴粗筛与张力门分开使用：

| 分诊轴 | 对应检查 | 去向 |
|---|---|---|
| 人物动机 | 张力门「想要」，再看行动与代价是否证明 | 剧本层 |
| 剧情反转 | 张力门「转折」及前向铺垫、后向回收 | 剧本层 |
| 人物台词 | 张力门无对应行 | `human-texture-and-script-gate.md` |
| 冲突推进 | 张力门「升级」及场后状态变化 | 剧本层 |
| 结尾卡点 | 张力门「结尾 + 钩子」，连载再查承接 | 剧本层 |

症状先分流：与前文承诺不一致，先修状态载体；开头乏力、冲突不够或台词直白，先修创作发动机与张力门。需要状态补救时按症状叠层：结局/设定漂移用全局真源，长稿装不下全文用摘要注入，相邻场断裂用分场接力；短稿不强上三层。

生成侧先落入身份漂移、物理失真、提示词误读、帧间时间不一致、参考低质/错配之一，再进入下方五层。诊断只判断，不在同一轮顺手改出一版新稿。

## 2. 诊断报告与返工量

失败诊断输出固定四段「现象→原因→修复→重测」；「修复」必须点名 NBP v2 字段 `characters/scene/action/camera/aspect_ratio/duration/audio/references/continuity/negative` 或适配器参数名，「重测」只改一个变量并写明是哪一个。
1. 先声明评审角色与体裁基准；结构、推进力、人物、台词、悬念、平台、商业按适用项分组，可用 1–5 五级并逐项记录依据。没有明显问题可写「暂未发现明显问题」，禁止为填满模板而凑错。
2. 问题按影响观众理解与追看欲排序，修改意见必须落到具体场、句或镜头；评分只用于排序。
3. 硬伤只列四元组：`维度 + 分数 + 坐标 + 建议`，且只列 `≤3 分` 项。AI 味可作为带依据的定位维度，也可分别看口语化、可切片时刻；不得拿分数代替人读判断。
4. 返工量只取：`可拍 / 小改 / 重写 30–50% / 推倒重来`，依据写受影响场次数或结构层级，不由总分换算。
5. 可执行改法只列最严重三处，最后再收敛为当前只改的一处、时间盒与杠杆理由；不得新增人物/设定或偷改故事核心。

**门是二值，分数只定位，不进任何门。** 注水等专项也先做整体定位再逐段细查，避免诊断与重写互相遮蔽。

## 3. 剧本层

| 卡 | 现象 | 原因 | 修复 | 重测 |
|---|---|---|---|---|
| FD-01 | 补出的设定混成既定事实 | 信息不足时静默补写 | 每条新增事实标「补充设定」，不得改核心方向 | 重跑设定差异，看标记与核心方向 |
| FD-02 | 后段丢伏笔、人物或结局漂移 | 状态超过单轮可携带范围 | 外置真源并每轮重注入，不在坏稿后追补 | 从断点续写，查伏笔、人物、结局 |
| FD-03 | 角色用说明书式台词宣告动机 | 行动链未证明欲望 | 暂删解释台词，用选择与代价重写；对白另走人味门 | 静音读场，看动机能否由行动成立 |
| FD-04 | 反转有铺垫却不成立 | 只向前查，未向后回收 | 排除新人物、新证据、新身份、新设定驱动；让旧线索获得新解释 | 前后各读一次，查铺垫与回收 |
| FD-05 | 装置/世界观、样式或情绪很满，局面没变 | 冲突只产情绪，风格冒充内容 | 每场至少改变关系、利益或剧情方向之一 | 对比场前后状态；全空即删或改行动 |
| FD-06 | 标签拼盘或饱和题材掩盖主线 | 没先确认目标、阻碍与轴心差异 | 先查主线，再依次查因果、动机、信息、时空、关系、反派、反转、节奏、钩子 | 从主线向下复跑；上层不过则停止 |
| FD-07 | 误会靠角色不说维持 | 信息一开口即可取得 | 改成拿不到、说了不被信，或说出口有即时代价 | 让旁观者尝试一句话解局，仍能解则失败 |
| FD-08 | 扁平反派突然犯蠢送结果 | 行为只服务作者需要 | 问是否有更简单做法；若有，补不知情、约束或更大代价 | 以反派视角重跑选择，看最优路径是否可信 |
| FD-09 | 合理犯错被误判为漏洞 | 审稿用了全知视角 | 复原角色此刻所知与情绪，再判漏洞或人物选择 | 只用角色当时信息重审该步 |
| FD-10 | 信息差、悬念、审美或外部代写被混进漏洞清单 | 未分类，也把创作判断外包 | 候选先分真漏洞/信息差/悬念/审美；创作判断留在当前会话。带原始链接的搜源、交叉核验与反方质疑仍属研究 | 清单只保留真漏洞，并核对核心未被外改 |
| FD-11 | 被毙后只抛光台词 | 未先找最高层根因 | 按铺垫→台词→出场顺序最小修，三级无效才动情节/动机 | 重跑原失败轴，不以文句变顺代替通过 |
| FD-12 | 交付范围错位，或薄 brief 不诊断就写全本、只赞不查 | 缺信息被脑补，输入/交付未对齐 | 缺项列「需要作者补充」；按用户要剧本/成片/发布选产物 | 对照 brief 查未知项标记与交付物 |
| FD-13 | 开头默认旁白交代背景 | 「开头」被理解成说明设定 | 把第一句载体写成动作或台词；禁旁白只用于纠默认偏好 | 重跑开头，看首句形式及疑问/反差 |
| FD-14 | 有钩子外形却无续看力 | 异常不异常、信息差无差、时限不收窄选择 | 点名异常/信息差/时间压力及具体画面，指不出就换法 | 看最早可读帧及后文兑现 |
| FD-15 | 背景一次由长台词倒完 | 小说式说明压断短剧节奏 | 在原稿把背景拆进冲突与行动，不先推翻全稿 | 朗读并查每段背景是否伴随状态变化 |
| XA-01 | 出海版台词语域与角色身份／年龄／目标语言不符；同一角色不同年龄或剧情阶段共用一组参考图，脸与装扮漂移 | 本地化只翻译不重写；阶段形象未分版本 | 语域按角色与目标语言重写（human-texture-and-script-gate.md）；按剧情阶段分版本资产、共享身份锚（keyframe-assets.md） | 换角色朗读语域；同一阶段取两镜比脸与装扮 |

## 剧本对位防错卡

用于生成结果和剧本对不上的情况：台词、说话者、语气或节拍错位。先跑 `python3 scripts/check_script_coverage.py`（用法见 [prompt-compiler.md](prompt-compiler.md#剧本锁编译)）。对账不过，是规格层的错，先修规格，不急着重新生成；对账通过但成片仍错，才算模型执行层的问题。

| 卡 | 现象 | 原因 | 修复 | 重测 |
|---|---|---|---|---|
| SF-LINE | 成片台词被改写、漏说或多出一句 | 规格里的台词已偏离剧本，或同一句在 prompt 里出现两次，被当成两遍 take | 修 `audio.dialogue[]` 回到剧本原句；有 `beats` 时台词只出现在分段内，结尾只声明句数；超过口播密度就回剧本删半句 | 对账退出码 `0` 后只重生这一镜，逐字对听 |

| SF-TONE | 词都对，但语气与此刻关系不符（该压着说却在喊，该试探却像宣告） | 模型只看得到这一句，看不到上一场的欲望和处境；语气括号写成了抽象情绪词 | 语气括号改写成可演的发声与身体提示（压低、说一半停住、不看对方）；把上一场留下的状态写进 `action` 或 `characters[].state`；`script_ref.context` 只给人看，不进 prompt | 只改语气提示这一处，盲听判断关系是否读对 |
| SF-BEAT | 动作和台词先后颠倒，或镜头演的是另一个 beat | 台词没有时间位置，动作与台词挤在一段；`script_ref.source_beats` 和剧本对不上 | 用 `beats[]` 给出 `start_s/end_s`，台词放进它真正出口的那一段；修 `script_ref.source_beats`；动作过载就拆镜 | 只改分段时间，连播核对动作与台词的先后 |

## SPEC v2.0 盲审 FAIL 的靶向路由与错题回写

Clean-Room 判卷（`scripts/eval_harness.py post-gen`）给出的 `repair_route` 与上表分层一一对应：`slow_or_split_shot` → 提示词层动作密度与 `OPEN ON ACTION`；`boost_identity_anchor` → 资产层锁定视图与参考职责；`cross_stage_rollback_stale` → 回退 Step 2/3/4 并 `drama_setup.py invalidate` 作废波及镜头；`post_clean_plate_fix` → 后期层干净底板与切点。仍守「每次只改一个变量」，单镜自修 ≤2 轮、全片重渲染 ≤30% 且 ≤5 次，触顶用 `eval_harness.py escalate` 交人工。复现的新错型按 `harness-guardrails-and-eval.md` 第 10 节经 `scripts/mistake_book.py add` 去重、合并、冲突检查后入库，再跑 `mistake_book.py tier1-run`。

## 8. 抖音模块追加诊断

仅在抖音模块启用时使用。

| 现象 | 原因 | 修复 | 重测 |
|---|---|---|---|
| 开场吸引弱（仅在抖音模块启用时使用） | 首个可读时刻没有真实异常、信息差或时限压力 | 换成可见动作/关系变化，并标后文兑现点 | 在目标竖屏裁切下看首个可读画面与兑现 |
| 节奏平（仅在抖音模块启用时使用） | 相邻段落没有信息、关系、目标或情绪变化 | 删重复说明，给每段一个变化与切点理由 | 完整播放，逐段标变化与空转区 |
| 结尾驱动弱（仅在抖音模块启用时使用） | 只悬空，没有代价与同一问题的承接 | 写可视化卡点、未付代价、下一条承接问题 | 将下一集开头接上，核对是否同一欠账 |
| 竖屏构图不合理（仅在抖音模块启用时使用） | 主体、字幕或关键动作离开竖屏安全区 | 按目标画幅重排主体层级与动作路径 | 用真实竖屏画布查裁切、遮挡与可读性 |
| 对白不口语（仅在抖音模块启用时使用） | 角色替作者解释背景和主题 | 朗读删书面连接词，让台词服务当下动作；字幕确定性制作 | 真人朗读并对照字幕逐字复核 |
