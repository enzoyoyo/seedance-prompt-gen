
# 质量门禁与双阶盲审架构规范（SPEC v2.0）

> **设计原则：克制约束、动态解耦、锚点守恒、预算可控**
> 1. **顺势贴合执行链**：所有门禁直接嵌入真实的工作流步骤与脚本入口，区分纯提示词交付与工具渲染交付，不脱离真实可执行链路堆砌繁琐步骤。
> 2. **动态创意解耦**：严格执行**「动态创意解耦、刚性底线锁死」**，保障主体、运镜与风格的自由创作空间，只对高风险缺陷做结构化零容忍守卫。

---

### 0. 核心边界原则
- **克制约束原则（No Blind Over-Engineering）**：每项门禁均对应具体画质、连续性或合规风险；适配不同运行形态（纯提示词交付、脚本驱动或工具直连渲染），避免过度工程。
- **动态解耦原则**：严格执行**「动态创意解耦、刚性底线锁死」**——主体动作、镜头调度、光影氛围、视觉风格、单镜时长随选题自由推理，仅做必填结构槽位（Schema）完整性校验，严禁固化死板创意套路；全部工程约束聚焦于画质下限、跨镜头锚点一致性与负面崩坏零容忍。

### 1. Harness 底座：模块化拓扑与两级负面防护
- **渐进式目录架构**：主入口文件保持精炼，仅承载全局状态机、交互门禁与阶段路由；详细的提示词规范、运镜词库、审片判卷表、条件错题库作为独立子文件按需加载，防止单文件膨胀稀释注意力。
- **两级负面防护（防止禁令膨胀压制创意）**：
  - **L0 常驻极简底线（不超过 5 条）**：仅卡任何题材都零容忍的底层硬伤（画质严重涂抹模糊、人体/手指数量畸变、无故黑帧或切镜爆闪、乱码水印字幕）。
  - **L1 条件触发规则（Conditional Rules）**：严格采用 `IF [触发特征：如多人近身交互 / 手部持物特写 / 大幅环绕运镜 / 复杂光影切换] THEN [挂载专属约束 & 审片重点项]` 结构；未命中触发条件严禁挂载。

### 2. Eval 工程：双阶独立盲审与二元判据
- **Pre-Gen Eval（生成前文本逻辑审校）**：核查动态创意 Schema 无漏填；**单镜时长与动作密度匹配**（拦截短镜头塞入超载连续动作）；前后镜头角色服装/光影/空间方位锚点自洽；命中的 L1 条件防护已准确注入。
- **Post-Gen Eval（生成后 Clean-Room 独立视觉盲审）**：
  - **模型与上下文强制隔离**：必须使用独立于生成环节的视觉多模态模型（优先异构模型；同模型家族则必须开启全新无状态 Clean-Room 上下文，严禁传入生成推理历史），仅输入：`[待审视频或抽帧拼图] + [角色/场景/白模基准锚点图] + [本镜预期动作一句话摘要] + [二元判卷表]`。（若本 Skill 当前处于“仅出提示词”模式，则提供轻量级人工回传成片/截图触发盲审的入口，不强行伪造自动渲染管线）。
  - **双轨视觉采样标准**：
    - 支持原生视频流时：输入**低码率完整片段**（专查人物滑步、物理变速异常、切镜微频闪等帧间时序崩坏） + **首帧、尾帧、动作峰值帧、切镜前后帧高清图**（与基准资产图同屏比对人脸漂移、服装串色、手部肢体畸变）。
    - 仅支持图像输入时：按 `2 fps 均匀抽帧 + 首帧 + 尾帧 + 动作峰值帧` 生成带时间戳编号的序列拼图（Contact Sheet）送审。
  - **原子级 Yes/No 判卷表与正反例阈值**：废除主观模糊打分，每类缺陷定义为独立是非题（触碰任一红线即判 `FAIL`），且**每项判据必须配套 1 个 PASS 正例 + 1 个 FAIL 反例**（例如：高速挥剑产生的自然运动模糊判 `PASS`，手指融化粘连或多指错位判 `FAIL`）。

### 3. Loop 闭环：靶向自修、全局预算熔断与跨阶作废协议
- **靶向归因自修**：Eval 判 `FAIL` 时自动按根因执行修复（动作畸变 → 降速或拆分为两个镜头；身份漂移 → 提高锚点描述与参考图权重；空间穿帮 → 触发跨阶段回退）。
- **双重预算熔断（防烧穿额度与死循环）**：
  - **局部上限**：单个资产或单个分镜自修重跑 **≤ 2 轮**。
  - **全局上限**：整片累计视频重渲染次数 **≤ 总镜头数的 30%（且硬上限不超过 5 次）**。
  - **熔断出口**：触及任一上限立即停止自动重试，汇总「问题帧截图 + 失败根因 + 已试方案 + 拆镜/改词建议」交由人工裁决。
- **跨阶段回退与脏产物作废（Artifact Invalidation）**：
  - 若 Step 6（分镜视频）检出根因属于 Step 2/3/4（角色/场景/白模空间站位硬伤），回退修正源头阶段，仅将**受该源头变更波及的下游白模与分镜显式标记为 `STALE`（强制重生成）**，未受波及的独立镜头保留有效状态。
  - 凡修改 Step 2/3/4 基准视觉资产或白模站位，**必须针对变更部分重新触发增量人工确认（Human Gate #2）**，严禁跳过确认直接重跑批量视频。

### 4. Graph 自进化：错题生命周期治理与成本分层验证
- **错题库治理（防无限膨胀）**：运行中捕获的崩坏或人工打回废片，按「触发条件标签 + 根因 + 修复规则 + 回归考题」写回持久化错题库；写回前强制执行**语义去重、同类合并与规则冲突检查**，并维护命中计数与状态标记，支持将长期零复现或误伤创意的旧规则标记为 `DEPRECATED` 下线归档。
- **成本分层验证**：
  - **Tier-1 零成本静态回归（每次修改必跑）**：用错题库全量考题纯文本测试 Pre-Gen Eval 拦截率与 L1 条件触发准确度（零视频 API 消耗）。
  - **Tier-2 故障注入真实冒烟（重构终验与审片变更必跑）**：仅低规格渲染 **2～3 个测试镜头**（强制包含 **1 个正常叙事镜头 + 1 个故意植入历史必崩写法的故障注入反例**；若本 Skill 未直接配置视频渲染 API，则使用本地历史真实废片/截图实测盲审链路），验证 Post-Gen 盲审真能拦截并触发自修。

### 5. 不可跳步端到端 SOP 与显式模型门禁
- **强制显式模型门禁（STOP & WAIT）**：任何实际生成启动前，优先调用宿主原生交互提问组件（无组件则输出编号选项菜单并**立即终止本轮回复挂起等待**），结合当前宿主实际支持的模型生态，由用户自主选定：
  1. **图片生成模型**（必选）
  2. **视频生成模型**（必选）
  3. **音频方案**（显式选择：BGM 生成模型 / 配音与音效模型 / 本项目无需生成音频）
  4. **全局规格与交付模式**（画幅比例、总时长与镜头节奏、风格基调、根据本 Skill 实际能力选择「仅输出结构化提示词」或「直接调用工具渲染成片」）
  *铁律：严禁跳过确认或静默预设默认值，严禁在同一回合内替用户自问自答往下执行。*
- **七步标准流水线（上一阶段未达标严禁流入下一阶段）**：
  `Step 1: 深度需求分析 + 条件错题预筛 + 全局规格与模型门禁确认 [Human Gate #1]`
  `→ Step 2: 角色标准资产图设定 [Eval & Loop]`
  `→ Step 3: 场景空间设定 [Eval & Loop]`
  `→ Step 4: 建模白模与空间站位/机位规划 [Eval & Loop]`
  `→ Step 5: 视觉资产与白模空间站位定稿确认 [Human Gate #2，进入高成本批量生成前唯一必停卡点]`
  `→ Step 6: 分镜提示词精修、视频生成与音频合成 [逐镜双阶 Eval & 全局预算管控 Loop]`
  `→ Step 7: 全片连贯性终检交付 + 新发典型错题去重入库`
  *安静执行铁律：除 Human Gate #1、Human Gate #2（含跨阶回退增量确认）及触发预算熔断上报外，中间质检一律静默自修，严禁中途频繁提问打断用户。*
