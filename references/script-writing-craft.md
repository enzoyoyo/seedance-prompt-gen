# AI 短剧剧本写作：可演、可拍、可逐句对账

本模块只管「剧本正文怎么写、按什么格式交」。张力八行见 [dramatic-tension-engine.md](dramatic-tension-engine.md)，审稿信号与中文表达审校见 [human-texture-and-script-gate.md](human-texture-and-script-gate.md)，冲突／逆转爽剧手法与对白四个动作见 [story-short-drama.md](story-short-drama.md)，剧本进镜头见 [prompt-compiler.md](prompt-compiler.md#剧本锁编译)。这里不重复它们，只补三件事：格式、写作顺序、写作期就规避生成失败。

## 1. 为什么 AI 短剧要专门的剧本格式

真人演员读完整本剧本，知道前情、知道自己在对谁说、知道这句话为什么这样说。视频模型每次只看到一镜的 prompt：前一场发生了什么、这句话是回应谁的、说话的是哪张脸，它都不知道。台词被改写、说错人、语气不对上下文，多半是剧本没有把这些信息写成可搬运的形式，在转成 prompt 时丢了。

所以 AI 短剧剧本比传统剧本多三条要求：

- 每个 beat 有稳定编号，镜头用编号引用它，可以机械对账；
- 说话者名字就是身份键，和资产、`characters[].name` 逐字一致；
- 前情写成可搬进单镜的「承接」，不指望模型自己记得。

## 2. 格式约定

```text
## S3 档案室 夜 内
人物：Mira、阿哲
【承接】Mira 以为全楼只有她手里这一把钥匙。
【本场目标】Mira 要弄清是谁开的门，又不能让门外的人听出她在怕。
【禁止】不出现第三把钥匙；阿哲本场不露脸。

[S3-B1] △ 锁舌咔地一响。Mira 攥着铜钥匙，指节发白。
[S3-B2] △ 她连头带肩转向封死的门，屏住呼吸。
Mira（压低）：谁开的？
[S3-B3] △ 门缝里伸出一只手，把一串钥匙放在地上。
阿哲（画外）：你那把，是我配的。
[S3-B4] △ Mira 没去捡。
Mira：……那原来那把呢？
```

| 元素 | 写法 | 进入生成时去哪 |
|---|---|---|
| 场景行 | `## S编号 地点 时间 内/外`，一场一个标题（放在 `## 剧本正文` 下时用 `###`） | `scene`；标题会重置 beat 归属 |
| 人物行 | 本场出场者，名字与资产名一致 | `characters[].name` 与参考槽 |
| 【承接】 | 进场前角色已知道什么、刚做过什么、身上带着什么状态 | 看得见的部分进 `characters[].state` / `action`，其余进 `script_ref.context`（只留在笔记，不进 prompt） |
| 【本场目标】 | 谁要从谁手里拿到什么；每句台词都要服务它 | `acting_task` 与语气括号 |
| 【禁止】 | 本场不能出现的事实，防模型补戏 | `negative` |
| `[S3-B2]` | 场号-拍号，全剧唯一；一个 beat 只写一次可见变化 | `script_ref.source_beats` |
| `△` 行 | 一行一个看得见或听得见的动作、声音、物件变化 | `action`、`beats[].action`、`audio.sfx` |
| 台词行 | `角色名（语气）：台词` | `audio.dialogue[]` 与 `beats[].say`，逐字搬运 |
| 画内文字 | `【画内文字】…` / `【字幕】…` 单独成行 | 后期，不进生成 prompt |

台词行的三条规矩：

- **名字即身份。** 全剧同一个人只用一种写法；不用「他」「男人」「众人」当说话者。无名角色给一个固定代号（如「灰夹克」），从头用到尾。群声拆成具体几个人各说一句，或改成 △ 行里的环境声。
- **括号只写怎么说。** 括号里写发声、视线与面部的可演提示：压低、笑着、不抬头、抢话、照常的语气。走位、拿道具、转身另起 △ 行。不写「伤心地」「愤怒地」这类判断，写成演员能执行的动作。
- **画外与旁白分开。** `阿哲（画外）`：人在这个时空里，只是不在画面中。`旁白：`：叙述者不在这个时空里。两者都不对口型，生成时不绑任何一张脸。

正文只放上表这些元素。时长预估、自检表、检查点、阶段与结算标注、模板标签（如「预估 90.8 秒」「【本集结算】」「证据档1」）都不夹进场次和台词之间；需要时放在正文前后的独立小节。只有本 Skill 自己的镜头编译会读 beat 编号和三槽。稿子要交给读不懂它们的地方（给人读稿、外部短剧 Agent），就另存一份干净版：只留场景行、△ 行和台词。原稿保留编号，留着对账用。

## 3. 写作顺序：先静音，后台词

1. **定发动机与本场目标。** 按 [dramatic-tension-engine.md](dramatic-tension-engine.md) 定想要、阻力、代价，把每场的【本场目标】写成一句「谁要从谁手里拿到什么」。
2. **只写 △ 行排 beat。** 先不写任何台词，读一遍 △：观众能否看懂谁想要什么、哪里受阻、结果怎样。看不懂就改动作，不加台词补救。
3. **再加台词。** 每句先定它在办什么事：试探、压价、遮掩、拖延、拒绝、激将、求和、认输、逼表态。办不了事的句子删掉。一句只办一件事，对白技法按 [story-short-drama.md](story-short-drama.md) 的四个动作。
4. **出声朗读并估时。** 读不顺、一口气说不完的句子拆开或删字。时长粗估见第 5 节。
5. **编号、审校、对账。** 给 beat 编号，按 [human-texture-and-script-gate.md](human-texture-and-script-gate.md) 做表达审校；进制作前分镜后跑 `scripts/check_script_coverage.py`。

## 4. 台词与旁白：写作期最常见的五个坏习惯

审稿信号的全表在 human-texture-and-script-gate.md，这里只列 AI 生成剧本最常犯、改起来最快的五个：

| 坏习惯 | 例 | 改法 |
|---|---|---|
| 旁白解释心情 | 「我不知道哪来的勇气」 | 删掉，换成一个动作：他把扫码枪放下了 |
| 台词点题 | 「这是三十天里第一个人跟我说话」 | 让人物回避、答非所问，或交给一个物件 |
| 复述画面 | 画面已见泼水，台词再说「你把水洒了」 | 台词只加画面给不了的：立场、谎言、要求 |
| 角色可互换 | 两人对调台词仍成立 | 从身份、处境和此刻要办的事重写用词，不靠口癖 |
| 字幕揭底 | 结尾黑屏字幕交代身世 | 揭示用的人、物、信息必须在前文出现过，转折里主角要有动作 |

旁白只给画面给不了的东西：时间跨度、不在场的事实、叙述者此刻的判断。它不翻译画面，也不替观众总结感受。

## 5. 为 AI 生成而写

这些是写作期就能避开的生成失败，出了问题按 [failure-diagnosis.md](failure-diagnosis.md#剧本对位防错卡) 的 SF 卡排查：

- **一个 beat 一个说话者。** 两人来回说，拆成两个 beat，对应正反打或两个分段。同一 beat 里两人都说话，模型容易让两张脸同时动嘴（SF-SPEAKER）。
- **台词长度跟着时长走。** 校验器在 `beats[]` 里超过 5 汉字／秒时报 `DIALOGUE_TOO_DENSE`。这是本 Skill 的经验阈值，各模型实际语速待核实。超了就删字或把 beat 拉长，不指望模型加快语速。
- **前情写进【承接】，不塞进台词。** 让台词自己交代前情，对白会变成说明书。【承接】不写，单镜又不知道语气从哪来（SF-TONE）。
- **同一道具只用一个叫法。** 「铜钥匙」不要一会儿叫「钥匙」、一会儿叫「那把锁」。名词稳定，资产 id 才稳定。
- **一个 beat 的起止能一条动作路径连起来。** 连不起来就拆 beat，不让模型插值硬变。
- **剧本里不写 BGM，台词行不带字幕。** 音乐与字幕在后期做；写进台词行，模型可能把它唱出来或画成伪字。

## 6. 改写示范：深夜便利店

某初稿负例的前提有抓手：男人连续三十个深夜来买一瓶水，用硬币付钱，站在收银台前喝完才走。问题出在写法：

| 原稿写法 | 问题 | 改法 |
|---|---|---|
| 店员旁白解释自己的孤独与勇气 | 心情靠说 | 删掉旁白，换成店员替他垫一枚硬币这个动作 |
| 男人说出主题句 | 点题 | 改成回避式回答，把分量交给地砖 |
| 结尾字幕交代「刚办完离婚手续」 | 转折无铺垫，靠字幕揭底 | 删掉字幕；前文先埋挂号单和同一块地砖，观众自己拼 |
| 代价写「丧失信念」 | 抽象，不可计量 | 店员在监控下替顾客垫钱，违反夜班规定 |
| 台词括号里写调度与机位 | 括号混进调度 | 调度拆成 △ 行，括号只留怎么说 |
| 没有 beat 编号 | 无法对账 | 按场号-拍号编号 |

改写后的一场：

```text
## S1 便利店收银台 夜 内
人物：邝姐、灰夹克
【承接】第三十一夜。灰夹克每晚同一时间来，用硬币买一瓶水，站在收银台前同一块地砖上喝完才走。夜班规定不许和顾客闲聊，监控正对收银台。
【本场目标】邝姐想知道他为什么每晚都来；灰夹克只想喝完这瓶水，不被人问。
【禁止】不用旁白解释心情；不用字幕交代身世。

[S1-B1] △ 硬币一枚枚码在台面上。邝姐数到最后，停住：少一枚。
[S1-B2] △ 灰夹克摸遍口袋，只摸出一张折了四折的挂号单，又塞回去。
灰夹克（不抬头）：明天补。
[S1-B3] △ 邝姐抬眼看了一下头顶的监控，从自己口袋里摸出一枚硬币，按进收银机。
邝姐（照常报价的语气）：够了。
[S1-B4] △ 灰夹克拧开瓶盖，没有喝，低头看着脚下那块地砖。
灰夹克（很轻）：这块砖，以前是她站的。
[S1-B5] △ 邝姐没接话，把台面上的水渍擦干，抹布叠好放回原处。
邝姐（低头）：明天还是这个点？
△ 灰夹克点了一下头。这一次，他把空瓶带走了。
```

改了什么：

- 代价落到邝姐身上，而且在画面里：监控下替顾客垫钱。
- 转折由前文的物件托住。同一块地砖在【承接】里出现，挂号单在 B2 里出现；「她」是谁不说破。
- 每句台词都在办事。「明天补」是拒绝被照顾；「够了」是替对方圆场；「明天还是这个点？」是邀请，没有一句「明天见」式的表态。
- 结尾兑现为可见变化：空瓶第一次被带走。

这场只示范写法。成稿仍按 SKILL.md 打印剧本张力门与标题候选。

## 7. 交付前自检

- 删掉全部台词，只读 △，故事还在吗？
- 每句台词能说出它在办什么事吗？
- 说话者名字、道具叫法全剧一致吗？人名、机构名和剧名撞上 [open-creative-director.md](open-creative-director.md#anti-template-and-originality-checks) 的 model-default test 清单吗？
- 每个 beat 是否只有一个说话者，台词长度放得进它的时长？
- 转折用的人、物、信息，在转折前出现过吗？
- 进制作时，镜头 JSON 的 `script_ref.source_beats` 能覆盖全部 beat，`check_script_coverage.py` 退出码为 0 吗？
